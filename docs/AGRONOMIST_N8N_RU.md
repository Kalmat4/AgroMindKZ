# AgroMind KZ: помощник агроному по выбранной точке

Подготовлено для Kalmat4/AgroMindKZ, исходный main: 8a76241897d643e851eecdbf4a0d6a4b5410f590.

## Поведение

В разделе «ИИ Помощник агроному» выберите точку на карте либо введите широту и долготу. При желании укажите культуру, фазу роста и орошение. Нажмите «Сохранить участок», затем задайте вопрос или приложите фото. Точка и параметры сохраняются вместе с первым успешным ответом в текущем чате и восстанавливаются при его открытии. Новый чат начинает без точки.

Laravel получает прогноз для выбранной точки через существующий OpenWeatherMapService, термоточки через NasaFirmsService и передает в n8n структурированный JSON. Без точки используется центр выбранного/сохраненного региона с явной отметкой приблизительности; без региона помощник попросит координаты. Поиск термоточек — прямоугольник ±0.1° вокруг точки, обрезанный по глобальным границам; это не полигон поля и не фиксированный радиус в километрах. Для участков у линии перемены дат требуется отдельная поддержка разбиения bbox.

Погода: сводка до 5 дней и периоды до 48 часов, кеш до 30 минут. FIRMS: термоаномалии за 48 часов, кеш до 10 минут. Время assembled_at обозначает сборку контекста, не время обновления первоисточника. Пустой прогноз не передается как нулевые температура/осадки. Координаты запроса погоды округляются до 5 знаков; разрешение прогноза определяется провайдером.

Данных почвы, влажности, NDVI, лабораторных анализов и подтвержденных диагнозов в этой интеграции нет. По координатам они не выдумываются. Фото дает предварительные признаки, а не гарантированный диагноз. История включает до 10 текстовых сообщений, прошлые изображения не пересылаются.

## Подключение n8n

1. Импортируйте `n8n-workflows/agronomist-v2.json` как отдельный workflow.
2. В узле **Webhook** выберите Header Auth credential: имя заголовка `X-AgroMind-Secret`, значение — длинный случайный секрет. Такой же секрет укажите в Laravel. Не добавляйте его в Git или Vue.
3. В узле **Anthropic API** выберите другой Header Auth credential: имя `x-api-key`, значение — ваш ключ Anthropic.
4. В **Build Messages** проверьте `MODEL`. Сохранено исходное значение проекта `claude-opus-4-7`; доступность модели в вашем аккаунте здесь не проверялась. При необходимости поставьте доступный вам идентификатор модели с поддержкой изображений.
5. Опубликуйте/активируйте workflow и скопируйте Production URL из узла Webhook. Старый `crop-chat.json` не менялся; новый backend требует новый workflow.

В `.env` Laravel:

```dotenv
N8N_CROP_WEBHOOK_URL=https://YOUR-N8N-HOST/webhook/agromind-agronomist-v2
N8N_CROP_WEBHOOK_SECRET=YOUR_RANDOM_SECRET
OPENWEATHER_API_KEY=YOUR_WEATHER_KEY
FIRMS_MAP_KEY=YOUR_FIRMS_KEY
```

После обновления кода на тестовой среде:

```bash
php artisan migrate
php artisan config:clear
npm ci
npm run build
```

При использовании `config:cache` пересоздайте кеш после настройки. На reverse proxy и PHP нужен лимит тела запроса не менее 10 МБ и достаточное время ожидания: получение источников может занять до 25 секунд плюс до 90 секунд на n8n. Фото ограничено 5 МБ исходных байт и 8000 px по каждой стороне; MIME проверяется по содержимому. Webhook и API ключи только на серверах. Laravel уже требует авторизацию и ограничивает `/n8n/crop` до 20 запросов в минуту.

n8n возвращает `{ "response": "ответ" }` при успехе и HTTP 502 при ошибке модели. Ответы с ошибками не сохраняются как советы. Успешные и ошибочные production-executions отключены для сохранения в новом workflow; ручные executions могут сохранять введенные фото и координаты согласно настройкам вашей n8n-инсталляции.

## Проверки перед включением на основном сайте

В этой среде прошли `npm run build`, `node scripts/test-agronomist-workflow.mjs`, `git diff --check`. Сборка сообщила предупреждения о существующих `:deep` в глобальном CSS и размере JS-бандла. PHP/Composer в среде отсутствуют: выполнение Laravel, миграция и PHP-тесты не проверены. Workflow не импортирован в живой n8n, внешние API с вашими ключами не вызывались. Проверки Node проверяют код преобразования данных, но не заменяют выполнение workflow в n8n.

На тестовой среде проверьте:

- Точка 53.2, 63.6 + пшеница: в n8n `context.location.scope=selected_point`, координаты совпадают с выбором, источник прогноза относится к точке.
- Сохраненный чат после перезагрузки восстанавливает точку и культуру; новый чат не наследует их.
- Отправка фото JPEG передает `image` как base64 JSON и модель видит изображение.
- Недоступная погода/FIRMS дает `unavailable`, помощник сообщает о пробеле, а не об отсутствии угроз.
- Чужой `sessionId` дает 404, не вызывает n8n; неверные координаты дают 422.
- Неверный webhook secret отклоняется n8n; ошибка модели дает 502 и не создает сообщений в БД.
- Отправка без точки сохраняет обычный чат и явно использует приблизительный региональный контекст.

Выбранная точка сохраняется на уровне чата, не как отдельная сущность поля. Полигон, площадь, несколько сезонов и журнал агроопераций — отдельное расширение. Live-запуск потребует настройки credentials и проверки модели в n8n.
